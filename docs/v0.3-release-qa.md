# Trace v0.3 release QA

Este documento bloquea el tag `v0.3.0`. No se genera instalador final ni tag
hasta que estos tres bloques esten revisados con evidencia real.

## 1. Sugerencias inteligentes con vault real

Objetivo: confirmar que TF-IDF en `trace-core` produce conexiones utiles, no
solo matematicamente correctas.

Usa una copia de un vault real con 20-30 notas como minimo. El auditor abre la
base en solo lectura y no modifica datos.

```bash
cargo run -p trace-core --example suggestion_audit -- ./trace-data/trace.db 30 5
```

En Windows, si el vault es desktop:

```powershell
cargo run -p trace-core --example suggestion_audit -- "C:\ruta\a\vault\.trace\trace.db" 30 5
```

Revisar cada nota auditada:

- Top 3 util: al menos una sugerencia ayuda a conectar conocimiento real.
- Ruido: sugerencia relacionada solo por palabras comunes o tema demasiado amplio.
- Faltante: sabes que existe una nota relacionada y no aparece.
- Idioma: probar notas en espanol y en ingles si el vault mezcla ambos.

Criterio minimo para tag:

- 70% o mas de notas con top-3 util cuando deberian tener relacion.
- Menos de 25% de sugerencias claramente ruidosas.
- Cero sugerencias de pares ya conectados.
- Cero sugerencias de pares ignorados.
- Las notas inbox no aparecen como destino hasta procesarse.

Si falla:

- Mucho ruido: subir `MIN_SCORE` en `crates/trace-core/src/suggestions.rs`.
- Titulo exacto no sube suficiente: ajustar `title_mention_boost`.
- Ruido en espanol: ampliar `is_stopword`.
- Notas largas dominan: revisar pesos de `cosine` vs `overlap_score`.

Registrar resultado:

| Fecha | Vault | Notas | Top-3 util | Ruido | Decision |
| --- | --- | ---: | ---: | ---: | --- |
|  |  |  |  |  |  |

## 2. Windows instalado limpio

Objetivo: confirmar que lo que funciona en `tauri dev` tambien funciona desde
un instalador real.

Ambiente recomendado:

- Usuario Windows limpio o VM.
- WebView2 actualizado.
- Sin terminal de desarrollo abierta.
- Instalar `.msi` o `-setup.exe` generado por GitHub Actions.

Checklist:

- Crear vault nuevo y abrir Trace.
- Crear nota, editar titulo largo y confirmar wrap/tooltip sin romper layout.
- BlockNote carga; si falla, modo seguro guarda contenido sin perdida.
- `Ctrl+Space` abre captura rapida.
- `Enter` guarda nota en Bandeja de entrada.
- Bandeja muestra badge y permite procesar nota.
- Code runner detecta runtimes instalados.
- Code runner muestra estado claro cuando un runtime no existe.
- Stop/cancel del code runner termina procesos largos.
- Exportar Markdown de nota y vault.
- Abrir Settings y cambiar apariencia sin editar archivos.

Criterio minimo para tag:

- Ningun P0/P1 abierto en Windows instalado.
- Si BlockNote cae a modo seguro, queda documentado con version de WebView2.
- Code runner no depende del PATH de la terminal del desarrollador.

## 3. Docker end-to-end

Objetivo: validar self-host real, no solo `/health`.

```bash
docker compose up -d
```

En CI, el workflow Docker ejecuta el smoke test HTTP contra el contenedor y lo
repite despues de reiniciar con el mismo volumen:

```bash
npm run smoke:self-host
```

Checklist:

- Abrir `http://localhost:8080`.
- Completar `/setup`.
- Login funciona despues de recargar.
- Crear 5-10 notas por UI web.
- Crear dos notas con contenido relacionado y confirmar sugerencia.
- Aceptar sugerencia y confirmar relacion/backlink.
- Exportar vault Markdown.
- Descargar backup.
- Subir backup a restore preview.
- Confirmar restore escribiendo `RESTORE`.
- Revisar audit log en Settings.
- Reiniciar contenedor y confirmar que la sesion o refresh funciona como se espera.

Criterio minimo para tag:

- Flujo setup/login/notas/sugerencias/backup/restore pasa sin comandos manuales
  dentro del contenedor.
- El volumen Docker conserva datos tras reinicio.
- No hay errores persistentes en logs.
